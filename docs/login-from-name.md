# Как имя игрока превращается в адрес

Игрок в этой игре — это имя и пароль, как было в предыдущей версии. Почты
он не вводит и не видит нигде. Но Supabase Auth логинов не знает: он умеет
вход по адресу и по телефону, а своя таблица с паролями — ровно то, от чего
проект уходил. Поэтому адрес существует, но собирается из имени и остаётся
внутренним идентификатором.

Считает его `Quiz.auth.loginFor()` в `js/auth.js`. Одна и та же функция
работает и когда ведущий заводит аккаунт, и когда игрок входит, — иначе
заведённое было бы не найти.

## Правило

Пять шагов, все детерминированные: одно имя всегда даёт один адрес.

```
1. обрезать пробелы и в нижний регистр
2. побуквенно по таблице транслитерации
3. всё, что не a-z и не 0-9, склеить в один дефис
4. дефисы по краям убрать
5. если ничего не осталось — "player"; дальше + "@" + ACCOUNT_DOMAIN
```

На примере «Дядя Фёдор»:

```
"Дядя Фёдор"  →  "дядя фёдор"  →  "dyadya fedor"
              →  "dyadya-fedor"  →  dyadya-fedor@quiz.local
```

Домен лежит в `Quiz.config.ACCOUNT_DOMAIN`, сейчас `quiz.local`. Домена
такого не существует, и это намеренно: письма никуда не уходят, а
подтверждение почты в проекте выключено — иначе аккаунт на несуществующем
домене не смог бы войти никогда.

## Таблица транслитерации

Тридцать три буквы, `Quiz.auth.TRANSLIT`. Нестандартное стоит помнить:

```
а→a  б→b  в→v  г→g  д→d  е→e  ё→e  ж→zh  з→z  и→i  й→y  к→k  л→l
м→m  н→n  о→o  п→p  р→r  с→s  т→t  у→u  ф→f  х→h  ц→c  ч→ch  ш→sh
щ→sch  ъ→(ничего)  ы→y  ь→(ничего)  э→e  ю→yu  я→ya
```

## Примеры

| Имя | Адрес | Что сработало |
|---|---|---|
| `Алина` | `alina@quiz.local` | обычный случай |
| `Пёс` | `pes@quiz.local` | ё → e |
| `Юра` | `yura@quiz.local` | ю → yu |
| `Щербак` | `scherbak@quiz.local` | щ → sch |
| `Жужа` | `zhuzha@quiz.local` | ж → zh |
| `Хрюша Ы` | `hryusha-y@quiz.local` | х → h, ю → yu, ы → y |
| `Игрок Два` | `igrok-dva@quiz.local` | пробел стал дефисом |
| `Дядя Фёдор` | `dyadya-fedor@quiz.local` | разобрано выше |
| `Мария-Луиза` | `mariya-luiza@quiz.local` | дефис остался дефисом |
| `Алина 2` | `alina-2@quiz.local` | цифры уцелели |
| `Collin` | `collin@quiz.local` | латиница проходит как есть |
| `Ольга Ъ Ь` | `olga@quiz.local` | ъ и ь исчезли, хвост из дефисов срезан |
| `🎈` | `player@quiz.local` | не осталось ни одной буквы |

## Что сливается в один аккаунт

Обратная сторона правила: разные написания дают один адрес, то есть один
аккаунт.

| Эти имена | дают один адрес |
|---|---|
| `Алина`, `алина`, `  АЛИНА  ` | `alina@quiz.local` |
| `Пётр`, `Петр` | `petr@quiz.local` |
| `Оля!`, `Оля` | `olya@quiz.local` |
| `Алина Б`, `Алина-Б` | `alina-b@quiz.local` |

Первые три строки — то, ради чего это и сделано: человек входит, набрав имя
как привык, и не обязан помнить, ставил ли он «ё» и был ли там пробел.
Четвёртая — цена: «Алина Б» и «Алина-Б» одновременно существовать не могут,
второму при заведении скажут «игрок с таким именем уже есть».

## Углы, о которые можно споткнуться

**Имя совсем без латиницы даёт `player@…`.** Один такой игрок заведётся, а
второй уже нет — адрес занят. Имени из одних эмодзи нужна хотя бы одна
буква или цифра.

**Двух Алин не бывает.** Второй нужна фамилия или цифра. Отбивает это сам
Supabase, ведущий видит сообщение про имя, а не про адрес.

**Имя — это логин, поэтому таблицу транслитерации нельзя менять задним
числом.** Поменяете `TRANSLIT` или порядок шагов — и аккаунты, заведённые
раньше, перестанут находиться по своим же именам. Если правка всё же
понадобится, придётся тем же преобразованием переписать `email` в
`auth.users` у всех существующих пользователей.

**Переименование в `profile` адрес не меняет.** Вход навсегда остаётся тем
именем, с которым аккаунт заведён. Интерфейса переименования сейчас нет, так
что налететь на это можно только через базу.

**В поле входа принимается и адрес целиком.** За это отвечает
`Quiz.auth.addressFor()`: если в строке есть `@`, она уходит в Supabase как
есть. Это запасная дверь для трёх аккаунтов, заведённых до конвенции (у
«Ведущего» адрес `host@quiz.local`), и на случай, когда имя разойдётся с
логином.

```
"Алина"            → alina@quiz.local
"host@quiz.local"  → host@quiz.local
"  ПЁС  "          → pes@quiz.local
```

## Как перепроверить

Примеры выше — настоящий вывод функции, а не пересказ. Устареть они могут
только вместе с кодом, поэтому проверять их надо тем же способом: открыть
страницу (см. `CLAUDE.md`, «Verifying a change») и выполнить в консоли

```js
['Алина', 'Пёс', 'Дядя Фёдор', 'Ольга Ъ Ь', '🎈']
    .forEach(n => console.log(n, '→', Quiz.auth.loginFor(n)));
```

Если вывод разошёлся с таблицей — прав код, а этот файл пора править.

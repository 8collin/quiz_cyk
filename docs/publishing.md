# Публикация: репозиторий, ключ, регистрация

Три вещи, которые связаны крепче, чем кажется: где живёт репозиторий, что в
нём лежит открытым текстом и кто может завести себе аккаунт. Разбирать их
поодиночке бесполезно — решение по одной меняет ответ по двум другим.

## Где что

Remote настроен вручную: `git@github.com:8collin/quiz_cyk.git`, репозиторий
**публичный**. GitHub Pages пока не подключён.

## Ключ из репозитория не убираем

С GitHub Pages репозиторий — это и есть развёртывание: файл в `.gitignore`
до опубликованной страницы не доедет, и она не заведётся. Подставлять ключ
на деплое через CI можно, но это зависимость от тулчейна ради значения,
которое всё равно уезжает в каждый браузер, открывший страницу, — секретом
оно не станет ни на минуту. Инвариант про anon-ключ описан в `CLAUDE.md`.

Отсюда правило на случай, когда ключ всё же захочется «убрать»: **ключ не
прячут, ключ отзывают.** Формат `sb_publishable_…` отзывается поимённо, не
задевая остальные.

Переписывать историю ради этого смысла нет: на GitHub переписанные объекты
остаются доступны по SHA, да и форки с клонами никуда не денутся. Гигиена
от этого появится, утечка — не отменится.

**Порядок при замене:** сперва выпустить новый ключ, вписать в
`js/config.js` и проверить страницу, и только потом отозвать старый. В
обратном порядке игра ляжет в промежутке между двумя шагами.

## Регистрация оставлена включённой — сознательно

Ручка `/auth/v1/signup` открыта publishable-ключом независимо от того, есть
ли на неё кнопка в интерфейсе, а ключ по замыслу лежит в странице.
Проверено запросом с заведомо негодным паролем: ответ приходит про длину
пароля, то есть проверку «регистрация разрешена?» запрос уже прошёл.
Значит, посторонний может завести настоящий аккаунт, `handle_new_user`
выдаст ему `profile` с ролью `player`, дальше `join_game` — и он окажется
на табло.

Решено оставить как есть: игра домашняя, для своих, а посторонний максимум
попадёт на табло и убирается кнопкой «✕» у ведущего.

Второе соображение важнее первого: на этой же ручке держится кнопка
**«+ Аккаунт»** (см. `decisions.md`). Выключив регистрацию, вы выключите и
её, и заведение игроков вернётся в дашборд. Если однажды понадобится и
закрытая регистрация, и заведение из панели, единственный честный путь —
Edge Function с ключом `service_role` на стороне Supabase; в страницу такой
ключ не кладут ни при каких обстоятельствах.

Что при этом стоит помнить: `join_game` пускает в игру любого
аутентифицированного, так что «кто попал на табло» ограничено ровно тем,
кто сумел завести аккаунт.

Анонимный вход выключен (`anonymous_provider_disabled`) — вариант «игрок
вводит только имя, пароля нет вовсе» сейчас недоступен без правки настроек.

## Настройки Auth, на которых всё держится

| Настройка | Состояние | Что сломается, если поменять |
|---|---|---|
| Подтверждение почты | выключено | аккаунт на `@quiz.local` не сможет войти никогда |
| Регистрация по почте | включена | перестанет работать «+ Аккаунт» |
| Анонимный вход | выключен | ничего; включение откроет ещё один вариант входа |
